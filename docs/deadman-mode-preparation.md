# Permanent Deadman source preparation — unfinished source only

This public fork branch prepares canonical character entry, online protection and Doomsayer input for permanent world345. Source publication is for immutable review inputs only; no PR or Ready claim is made. It is **not a usable Deadman mode**, a complete content delivery, a causal baseline, or a runtime-accepted change. The bounded preparation003, preparation006 and preparation007 native runs failed their first main-profile fixtures; the other four cases did not run. Preparation008 observed four individual checks pass, then failed the second Deadman check before a removal menu was observed; conflict was unrun. Their source/input/raw remain retained. No intermediate XP formula has been chosen, and full-mode runtime or Ready delivery remains unadmitted.

The opt-in `DeadmanMode:enabled` option defaults off. No shipped or deployment world setting is changed. If explicitly selected in a disposable preparation deployment, it claims the canonical `deadman` character profile and **blocks all XP and all player-v-player combat**, including after protection expires or is removed. These are preparation locks, not asserted retail rules. Multipliers=false gains still pass the XP allow gate and are refused. There is no arbitrary rate setting or ordinary-XP fallback. The locks must remain until the full coherent implementation and exact inputs are reviewed.

No main save is copied and no new profile-copy/save service exists. The actual plugin loader catches registration errors, logs them and continues: this is **not deployment-wide rejection or a login-admission guard**. The finite conflict fixture only observes this actual composition; it never logs a character in or asserts successful refusal. Other modes with this option off and a legitimate single-mode configuration retain their existing profile/init behavior. Coherent mixed-configuration refusal remains an explicit source TODO.

The existing clock owner now writes its saved-plus-current-session online milliseconds into the *snapshot*, after persistent attributes were cloned. It does not flush/reset/mutate the live session while taking a snapshot. Logout still flushes before the normal save. The shared correction intentionally makes normal/league/hardcore snapshots capture their current online time too. No new clock or timer is introduced. Preparation008 observed the bounded snapshot/query/flush/offline-relogin assertions pass for main, league, hardcore and Deadman. The new plugin option will require generated world-configuration documentation through the repository's generator before any eventual publication.
